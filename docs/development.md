# 一期开发说明

更新日期：2026-10-18。当前已打通安装、登录、首页、个人设置和控制台管理，一期头像、完整审计查询和部分维护功能尚未完成。产品基线见 [设计入口](README.md)。

## 已实现

- `internal/app` 装配生命周期、CLI、HTTP 超时和优雅退出；入口仅负责信号与退出码。
- 配置按 CLI、环境变量、文件、默认值顺序读取；数据目录默认 `<cwd>/data`。YAML 严格检查格式，配置损坏进入维护状态。
- 32 字节主密钥、AES-256-GCM 数据库口令加密、按用途派生的 CSRF 密钥；Unix 私有权限及 Windows 受限 ACL；原子文件替换和进程独占锁。
- sqlx/MySQL 安装适配器、UTC 连接、可验证身份的 TLS、专用 schema 命名锁、嵌入式 goose 初始迁移。普通启动只核验，不自动迁移。
- 安装状态机、空配置与空库检查、持久化 `install.lock`、创始人 bcrypt 凭据、四项默认设置、系统身份和安装审计的种子事务。
- 中断检查点及 `setup recover`：保留原密钥；仅空 schema 可从头迁移；完整迁移可继续种子；已提交种子可补本地标记；部分 DDL 停止自动恢复。
- 安装 API、`/auth/csrf`、健康与就绪探针、请求 ID、结构化 `error.details`、严格 JSON、同源和 CSRF 校验、安装限流、API/静态资源独立 404。
- 系统设置的四项类型校验及聚合版本计算；没有开放任意 KV 写入。
- Dockerfile 固定 `/app`、UID/GID 10001 和 `/app/data`，基础镜像锁定版本。
- 已在 Linux Docker 容器连接 MySQL 8.0 实测：迁移、种子事务、安装、重启、显式迁移与并发进程保护通过。
- Vue 安装向导沿用已确认的居中卡片布局：欢迎、数据库、系统配置、创始人、完成；支持安装中和维护状态，不使用安装令牌或安装会话。
- 安装完成时，仅最终安装请求所在浏览器获得创始人会话；显示 5 秒倒计时及“立即进入首页”。已有安装的新访客仍需登录，安装页不会补发创始人身份。
- 登录、注册关闭/开放、退出、30 天持久化滑动会话；令牌仅保存在 HttpOnly Cookie，数据库只保存摘要。注册开关在事务中重新校验，成功后自动登录。
- 创始人保护、管理员互管与自身限制；用户逻辑删除、用户名保留、敏感变更撤销会话、管理员设置密码后首次登录强制改密。
- 控制台真实用户列表、筛选与分页、创建/编辑/角色/状态/重置密码/删除；系统概览的实时数量和最近五项审计事件。
- 四项系统设置读写、ETag 并发控制、幂等无变化处理、只读运行信息和当前数据库连接检测。
- Pinia 会话状态与 Vue Router 访问守卫；首页、登录与注册、个人设置、概览、用户管理和设置页按柔和微增强原型落实布局、中文排版、圆脚 LOGO、侧栏底部账号菜单及折叠导航。

安装存储接口位于 `internal/modules/install`，账号/会话/管理用例的 Store 与 Tx 接口位于 `internal/modules/identity`。接口签名不引用 MySQL、sqlx 或 SQL 事务句柄，适配器位于 `internal/store/mysql`；业务授权和并发版本校验与写入在同一事务内完成。此次复用已有七张表，无新增迁移。

## 本次交付验收与遗漏复盘

此前把安装、跳转和账号模块拆成技术步骤，完成安装后的验收只覆盖了页面可达，没有覆盖“创始人进入控制台完成管理”的用户流程；同时没有及时把新增会话规则同步到接口和正式界面。正式前端也曾仅沿用配色，偏离原型的布局和组件。现按完整使用流程验收：安装成功获得本人会话 → 倒计时/按钮进入首页 → 侧栏账号菜单/首页卡片进入控制台 → 修改资料、管理用户和设置 → 退出并重新登录；同时验证普通用户没有控制台权限，以及新浏览器不会获得创始人会话。页面按原型逐页核对，不能用“有同名页面”代替视觉验收。

安装落盘与首次登录是两个阶段：安装成功但会话创建失败仍返回已安装状态，前端转入正常登录；响应丢失时先读取状态，不重放安装或自动补发创始人身份。

## 本地启动

需要 `go.mod` 指定的 Go 工具链、Node.js 22.12+ 和 npm。构建脚本按锁文件安装前端依赖，执行 Vue/TypeScript 检查并构建 SPA。

```sh
bash scripts/build-web.sh
go run ./cmd/octodcp serve --listen 127.0.0.1:8080 --public-url http://localhost:8080
```

Windows PowerShell 可用 Git for Windows 的 Bash 执行第一条命令：

```powershell
& 'C:/Program Files/Git/bin/bash.exe' scripts/build-web.sh
go run ./cmd/octodcp serve --listen 127.0.0.1:8080 --public-url http://localhost:8080
```

数据目录默认是仓库根目录下被忽略的 `data/`；可用 `--data-dir` 改为其他持久化目录。`OCTODCP_PUBLIC_URL` 或 `--public-url` 应设置为浏览器实际访问的来源地址。配置缺失或为空且没有安装痕迹时进入安装欢迎页，随后填写数据库连接，检查和最终安装都要求空库。所有安装步骤成功后最后写入 `data/install.lock`；存在时跳过安装，配置或数据库异常进入维护状态。

`GET /healthz` 检查进程存活，`GET /readyz` 在未安装或正常运行时返回 200。`GET /api/v1/setup/status` 显示安装状态，响应不包含文件路径或数据库口令。安装端点的状态约束、CSRF 及请求格式见 [API 文档](api.md)。

## 数据库准备

准备 MySQL 8.0.16+ 的 8.x 专用空数据库，字符集 `utf8mb4`，应用账号使用该库的初始化权限。兼容目标为 8.0 和 8.4，当前不接受 MariaDB 或未经验证的更高主版本。

不要导入 `docs/schema.sql`。该文件仅供评审阅读，安装程序会执行 `internal/store/migrations/mysql/00001_phase_a.sql`。数据库服务可以独立部署；应用不负责创建库或数据库账号。

其他环境联调需要连接地址、端口、库名、应用账号及 TLS 要求；部署侧提供数据库口令，避免在 Git、日志或截图中保存。每个新环境分别验证网络、目录挂载、反代、运行用户及密码哈希成本。
